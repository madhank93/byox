## What this stage teaches

Until now a connection carried one request. HTTP/1.1 defaults to keeping it
open, so the handler becomes a loop — and that loop is only correct if your
framing has been correct all along. Every byte you over- or under-read in
earlier stages surfaces here as a corrupted second request.

## Go you'll reach for

- A `for { ... }` around parse-and-respond inside the handler.
- The single `bufio.Reader` created once, outside the loop.
- `io.EOF` from the reader as the signal the client hung up.

## Hints

<details><summary>Nudge</summary>

Loop until reading the next request line returns an error, then close.
</details>

<details><summary>Approach</summary>

Nothing about the response changes yet — no `Connection` header is needed while
the connection stays open, because staying open is the default.
</details>

<details><summary>The API</summary>

Distinguish "client closed cleanly" (`io.EOF`) from a real read error. Both end
the loop, but only one is worth logging.
</details>
