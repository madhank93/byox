## What this stage teaches

Reading a body is where the framing rule stops being theoretical. The body is
not "the rest of the connection" — it is exactly `Content-Length` bytes, and
reading one byte too many steals the start of the next request while reading one
too few leaves the connection desynchronised.

## Go you'll reach for

- `strconv.Atoi(headers["content-length"])`.
- `io.ReadFull(reader, buf)` — fills the buffer or errors, unlike `Read`.
- `os.WriteFile(path, body, 0o644)`.

## Hints

<details><summary>Nudge</summary>

A `POST` creates the file and answers `201 Created`; the `GET` from the previous
stage still serves it.
</details>

<details><summary>Approach</summary>

Allocate a `[]byte` of exactly the declared length and fill it. A single `Read`
call is allowed to return fewer bytes than the buffer holds — that is the bug
`io.ReadFull` exists to prevent.
</details>

<details><summary>The API</summary>

Read the body from the same `bufio.Reader` you parsed the headers with, so any
body bytes it already buffered are not lost.
</details>
