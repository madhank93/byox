## What this stage teaches

One connection at a time means a slow client blocks everyone. Moving the handler
into a goroutine is a two-word change in Go — the lesson is in what that change
implies: each connection now has an independent lifetime, and anything shared
between them needs to be safe.

## Go you'll reach for

- `go handleConn(conn)` inside the accept loop.
- `defer conn.Close()` at the top of the handler.

## Hints

<details><summary>Nudge</summary>

The accept loop should do nothing but accept. All reading and writing moves into
the handler.
</details>

<details><summary>Approach</summary>

Close the connection in the handler, not in the loop — the loop has already
moved on by the time the handler finishes.
</details>

<details><summary>The API</summary>

A failed `Accept` should not kill the server; log or ignore and continue the
loop. There is nothing shared yet, so no mutex is needed at this stage.
</details>
