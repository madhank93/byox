## What this stage teaches

Before any HTTP exists, something has to own a port. A TCP listener is a socket
bound to an address that the kernel queues incoming connections on; `accept`
takes the next one off that queue and hands you a separate connection socket.
The listener never carries data — it only produces connections.

## Go you'll reach for

- `net.Listen("tcp", "0.0.0.0:4221")` — returns a `net.Listener`.
- `l.Accept()` — blocks until a client connects, returns a `net.Conn`.
- `defer l.Close()` — releases the port when `main` returns.

## Hints

<details><summary>Nudge</summary>

The tester only checks that a connection to port 4221 succeeds. It does not
send bytes and does not expect a reply.
</details>

<details><summary>Approach</summary>

Bind, accept one connection, exit. Failing to bind should not panic — print an
error and exit non-zero, because "address already in use" is the failure you
will hit most often while iterating.
</details>

<details><summary>The API</summary>

`net.Listen` returns `(net.Listener, error)`; `Listener.Accept` returns
`(net.Conn, error)`. Bind to `0.0.0.0`, not `localhost`, so the tester reaches
you regardless of how it resolves the host.
</details>
