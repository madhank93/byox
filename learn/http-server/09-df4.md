## Core concept

Content negotiation: the client advertises what it can decode, the server picks
one and says which it chose. The rule that matters is that a server must never
apply an encoding the client did not offer — so the absence of a header, or an
unrecognised value, means send it uncompressed and send no `Content-Encoding`
at all.

## Go APIs

- The header map from stage 5, looked up as `accept-encoding`.
- `strings.EqualFold` for the comparison.

## Hints

<details><summary>Nudge</summary>

Two cases: the client asked for `gzip`, or it did not. Only the first gets a
`Content-Encoding` header back.
</details>

<details><summary>Approach</summary>

You are only echoing the decision here — the body stays uncompressed until
stage 11. Keep the "which encoding did we pick" decision in one place; the next
two stages both extend it.
</details>

<details><summary>Implementation</summary>

An unknown scheme such as `invalid-encoding` must produce a normal 200 with no
`Content-Encoding` — not an error.
</details>
