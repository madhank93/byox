## Core concept

Now the body actually changes. Two things follow from that, and both are easy to
get wrong: `Content-Length` describes the **compressed** bytes, and a gzip
stream is not complete until the writer is closed — the trailer with the CRC and
size is written by `Close`.

## Go APIs

- `gzip.NewWriter(&buf)` over a `bytes.Buffer`.
- `w.Write(body)`, then `w.Close()` — before reading `buf.Len()`.

## Hints

<details><summary>Nudge</summary>

Compress into a buffer, close the writer, then measure. Measuring first gives a
length that is short by the trailer.
</details>

<details><summary>Approach</summary>

`defer w.Close()` is the trap here: it runs after you have already read the
length. Close explicitly, in order.
</details>

<details><summary>Implementation</summary>

gzip output is not byte-identical across implementations, so the tester
decompresses rather than comparing bytes. Any valid gzip stream passes.
</details>
