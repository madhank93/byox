## What this stage teaches

Two features you already have, combined: many connections, each alive across
many requests. Nothing new is added to the protocol — what is added is time.
Bugs that a single quick request/response hid (state cached on the wrong scope,
a reader shared between goroutines) now have room to appear.

## Go you'll reach for

- Nothing new. This stage is a check on the shape of what you already wrote.

## Hints

<details><summary>Nudge</summary>

Per-connection state — the reader, the header map, any keep-alive flag — must
live inside the handler function, not in a package-level variable.
</details>

<details><summary>Approach</summary>

Scan for globals. Anything mutable at package scope is now shared by every
connection simultaneously; either make it per-connection or guard it with a
`sync.Mutex`.
</details>

<details><summary>The API</summary>

The served directory is read-only and safe to share. Writes from the `POST`
stage go to distinct filenames, so they don't collide — but two goroutines
writing the same `net.Conn` would, which is why one response is written by one
goroutine, start to finish.
</details>
