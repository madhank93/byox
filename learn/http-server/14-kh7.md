## What this stage teaches

The other half of keep-alive: how either side says "this is the last one".
`Connection: close` is a request the client makes and an answer the server
gives — you send the response for the current request, echo the header back, and
only then close. Closing first is what produces the truncated-response bug.

## Go you'll reach for

- The header map, read as `connection`.
- `strings.EqualFold(value, "close")`.

## Hints

<details><summary>Nudge</summary>

The request that carries `Connection: close` still gets a full, normal response.
It is the connection that ends, not the exchange.
</details>

<details><summary>Approach</summary>

Decide before writing: if the client asked to close, add `Connection: close` to
the response headers, write everything, flush, then break out of the loop.
</details>

<details><summary>The API</summary>

If you buffer responses through a `bufio.Writer`, `Flush` before `Close` — a
closed socket discards whatever is still sitting in the buffer.
</details>
