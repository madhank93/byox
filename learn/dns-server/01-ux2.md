## What this stage teaches

DNS runs over UDP, and that changes the shape of the code. There is no
connection, no accept loop, no stream: one `ReadFromUDP` returns exactly one
whole message, and the sender's address comes back with it because there is no
connection to reply through.

No framing problem at all — the datagram boundary *is* the message boundary,
which is why DNS messages must fit in one packet.

## Go you'll reach for

- `net.ListenUDP("udp", &net.UDPAddr{Port: 2053})`.
- `conn.ReadFromUDP(buf)` and `conn.WriteToUDP(reply, addr)`.

## Hints

<details><summary>Nudge</summary>

A 512-byte buffer is the classic DNS limit and plenty here.
</details>

<details><summary>Approach</summary>

Keep serving after each message — one datagram is one request, and the next
arrives on the same socket.
</details>
