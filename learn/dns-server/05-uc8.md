## What this stage teaches

Reading the header back: the same packing in reverse, shifts and masks instead
of shifts and ORs. And the response stops being fixed — the ID, the OPCODE and
the RD flag are **echoed from the request**, because a client matches replies by
ID and expects its own flags reflected.

## Go you'll reach for

- `binary.BigEndian.Uint16`, then `(flags >> 11) & 0xF` for the opcode.

## Hints

<details><summary>Nudge</summary>

RCODE is 0 for a standard query (opcode 0) and 4, "not implemented", otherwise.
</details>

<details><summary>Approach</summary>

Write one `parseHeader` returning a struct. Every later stage reads from it.
</details>

<details><summary>The API</summary>

`(flags >> 11) & 0xF` is the opcode, `(flags >> 8) & 1` the RD bit. Echo
both into the response along with the ID.
</details>
