## Core concept

Decoding a name walks the label lengths until the zero byte, and the parser has
to report **where it stopped** — the next question, and then the answers, begin
at that offset. A parser that returns only the value and not the new position
cannot read a second record.

## Go APIs

- A `readName(data []byte, offset int) (string, int)` returning both.

## Hints

<details><summary>Nudge</summary>

QDCOUNT says how many questions to read; loop that many times.
</details>

<details><summary>Approach</summary>

Return the offset from every reader you write here. Stage 7 makes that
essential, because a name's bytes and its logical end stop lining up.
</details>
