## What this stage teaches

Writing an object reverses the read, and the order is where people go wrong:
**hash first, compress second.** The SHA-1 is taken over the header plus the
content *uncompressed*, then those same bytes are compressed and written to the
path the hash names. Hashing the compressed bytes produces a repository no
other git can read.

## Go you'll reach for

- `crypto/sha1` over `header + content`.
- `zlib.NewWriter`, and `encoding/hex` for the printed hash.

## Hints

<details><summary>Nudge</summary>

`hash-object -w` prints the 40-character hex hash and writes the file.
</details>

<details><summary>Approach</summary>

Verify against real git: `git hash-object <file>` must produce the same hash
for the same content.
</details>
