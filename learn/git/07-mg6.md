## What this stage teaches

Half the difficulty of the course, and four ideas at once.

**Smart HTTP** is two requests: `GET /info/refs?service=git-upload-pack` to
discover refs, then `POST /git-upload-pack` saying what you want.

**pkt-line** frames that conversation: each chunk is prefixed with four hex
digits giving its own total length, and `0000` is a flush packet. It is
framing, not text — parse it by length.

**Packfiles** are how objects arrive in bulk: a `PACK` header, then objects
back to back, each with a variable-length header whose first byte carries a
3-bit type and whose size arrives in 7-bit groups, little-endian, high bit
meaning "more follows".

**Deltas** are the sting. Two of those types are not objects but instructions
to rebuild one object from another — a series of copy-from-base and
insert-literal commands. A delta's base may itself be a delta, so resolution is
iterative: keep applying whatever you now have a base for until nothing is
left.

## Go you'll reach for

- `net/http` for both requests.
- The zlib reader again — each packed object is individually compressed.
- A loop resolving deltas until the pending set stops shrinking.

## Hints

<details><summary>Nudge</summary>

Build it in stages: parse pkt-lines, then the packfile header, then
non-delta objects, then deltas.
</details>

<details><summary>Approach</summary>

Verify as you go — every object you unpack should hash to the name it was
stored under. That catches a size-decoding bug immediately rather than three
layers later.
</details>
