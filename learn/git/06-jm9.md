## What this stage teaches

A commit is a small **text** object — the only human-readable one — pointing at
a tree, at zero or more parents, and carrying author, committer and message.
History is nothing more than commits pointing at parents, and because the
parent hash is part of the content, rewriting any commit changes every
descendant. That is why a rebase produces new hashes.

## Go you'll reach for

- `fmt.Sprintf` for the body; the same object writer as before.

## Hints

<details><summary>Nudge</summary>

`tree <hash>`, then `parent <hash>` lines, then `author`, `committer`, a blank
line, and the message.
</details>

<details><summary>Approach</summary>

The timestamp format is `<unix seconds> <+0000>`. It is part of the hashed
content, so two commits made a second apart differ.
</details>
