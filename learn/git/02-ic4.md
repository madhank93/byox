## What this stage teaches

The object format, which is the heart of git. Every object is stored as
`<type> <size>\x00<content>`, zlib-compressed, at a path derived from the
**SHA-1 of those uncompressed bytes**: first two hex digits are the directory,
the remaining 38 the filename.

Content addressing means the name *is* the checksum — you cannot alter an
object without changing where it lives, which is what makes git's history
tamper-evident.

## Go you'll reach for

- `compress/zlib` to decompress.
- `bytes.IndexByte(data, 0)` to find the header terminator.

## Hints

<details><summary>Nudge</summary>

`cat-file -p` prints only the content, not the header.
</details>

<details><summary>Approach</summary>

Never `strings.Split` an object: blobs are arbitrary bytes and may contain
newlines or NULs.
</details>
