## Core concept

A `WHERE` clause filters rows before they are projected, and the order matters
for a subtle reason: you may filter on a column the query does not select. So
the pipeline is decode the whole record, test the predicate, *then* pick the
requested columns.

## Go APIs

- A parsed `column = 'value'` predicate compared per row.

## Hints

<details><summary>Nudge</summary>

String literals in SQL use single quotes; strip them before comparing.
</details>

<details><summary>Approach</summary>

Decode the whole record first, then test the predicate, then project. The
filtered column is often not one of the selected ones, so projecting first
throws away what you need to test.
</details>
<details><summary>Implementation</summary>

`strings.Trim(literal, "'")` strips SQL's single quotes. Comparison is on
the decoded text value, not on the raw record bytes.
</details>
