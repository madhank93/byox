## What this stage teaches

Reading a named column means mapping the name to a position — which you get by
parsing the `CREATE TABLE` statement stored in the schema. The column order in
that statement is the order of the values in every record.

And the trap that catches everyone: an `INTEGER PRIMARY KEY` column is stored
as **NULL** in the record, because it *is* the cell's row id. Read it naively
and you get a column of empty strings.

## Go you'll reach for

- A small parser for the column list inside `CREATE TABLE (...)`.

## Hints

<details><summary>Nudge</summary>

If a column comes back empty for every row, check whether it is the row id.
</details>

<details><summary>Approach</summary>

Parse the `CREATE TABLE` text once per table and keep the column order.
The position of a name in that list is the position of its value in every
record of that table.
</details>
<details><summary>The API</summary>

`strings.Index(sql, "(")` to find the column list, then split on commas and
take the first word of each. The row-id column still needs the cell's row id
substituted in — its record value is NULL.
</details>
