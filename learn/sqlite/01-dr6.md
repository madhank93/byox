## Core concept

A SQLite database is one file divided into fixed-size **pages**, and the first
100 bytes are a header describing the whole thing. The magic string
`SQLite format 3\x00` identifies it; the page size sits at offset 16 as a
2-byte **big-endian** integer.

Big-endian is worth noting because most on-disk formats you meet are
little-endian. SQLite chose network byte order throughout, so every multi-byte
number in this course reads the same way.

```
the file, as pages:

 byte 0                    100                        pageSize
 +----------------------------+---------------------------+----------------+
 |  100-byte file header      |  page 1 b-tree content    |  page 2 ...    |
 +----------------------------+---------------------------+----------------+
  ^                    ^
  |                    page size, 2 bytes big-endian, at offset 16
  "SQLite format 3\0"

page N starts at (N-1) * pageSize   -- page numbers are 1-based
```

## Go APIs

- `os.Open` and a 100-byte read.
- `binary.BigEndian.Uint16(header[16:18])`.
