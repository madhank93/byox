## What this stage teaches

Tables outgrow one page, and the b-tree stops being a single node. **Interior**
pages (`0x05`) hold child page numbers instead of rows, and their header is
**12 bytes** rather than 8 because of a trailing right-most child pointer.
Scanning becomes a recursive descent to the leaves.

This is the moment the format's name earns itself: it was a B-tree all along,
you had just only seen the root.

```
one table, several pages:

                    +---------------------+
                    |  interior  (0x05)   |   12-byte header:
                    |  keys + child ptrs  |   the extra 4 bytes are the
                    +----------+----------+   right-most child pointer
                     /         |          \
              +--------+  +--------+  +--------+
              |  leaf  |  |  leaf  |  |  leaf  |   8-byte header
              | (0x0d) |  | (0x0d) |  | (0x0d) |   rows live only here
              +--------+  +--------+  +--------+

counting rows on one leaf = its cell count.
counting rows in a table  = walk every leaf.
```

## Go you'll reach for

- A recursive walk: interior → children, leaf → rows.

## Hints

<details><summary>Nudge</summary>

Do not forget the right-most pointer in the interior page header — the last
child hangs off it, not off the cell array.
</details>
