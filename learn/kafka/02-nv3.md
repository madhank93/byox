## What this stage teaches

Two ideas that never change. Every message is prefixed with a **4-byte
big-endian length**, so the reader knows exactly how much to consume — no
delimiters, no ambiguity. And every response starts with the request's
**correlation id**, which is how a client matches replies to in-flight requests
on a connection it is pipelining over.

## Go you'll reach for

- `binary.BigEndian.PutUint32` for both the length and the id.

## Hints

<details><summary>Nudge</summary>

The length counts the bytes after it, not including itself.
</details>

<details><summary>Approach</summary>

Build the body first, then prefix its length. Computing the length up front is
where off-by-fours come from.
</details>
