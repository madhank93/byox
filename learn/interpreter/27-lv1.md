## Core concept

Evaluated numbers print **differently from parsed ones**: the parser printed
`42.0`, the evaluator prints `42`. Lox has one number type internally but
prints integral values without a decimal part, so `stringify` has to drop the
`.0` — a formatting rule, not a representation change.

## Go APIs

- A number branch in `stringify` that trims a trailing `.0`.

## Hints

<details><summary>Nudge</summary>

`42` evaluates to `42`; `10.4` stays `10.4`.
</details>

<details><summary>Approach</summary>

`strconv.FormatFloat(v, 'f', -1, 64)` gives the shortest exact form, which is
already what Lox wants for both cases.
</details>
