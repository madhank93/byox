## What this stage teaches

The one stage that adds a **phase** rather than extending one. Chain-walking
lookup has a subtle bug: a closure that captures a variable which is later
declared again in the same scope resolves to the wrong binding, because the
search finds whatever is there *now* rather than what was there at definition
time.

The fix is a **resolver**: a static pass between parsing and evaluation that
records, for each variable use, how many environments up it lives. Evaluation
then makes a fixed number of hops instead of searching — correct, and faster.

```
why a chain search is wrong, and hops are right:

  { var a = "outer";
    fun show() { print a; }     <-- captured when a meant "outer"
    var a = "shadow";           <-- same scope, declared again
    show(); }

  search at call time:  walk out until "a" is found  -> finds "shadow"  WRONG
  resolver at parse:    show's `a` is 1 hop up, slot "a" -> "outer"     RIGHT

the resolver walks the tree once, recording a distance per USE:

    print a;   -->  distance 1  -->  env.parent.values["a"]
    print b;   -->  distance 0  -->  env.values["b"]
    print c;   -->  (not found) -->  globals

evaluation then does a fixed number of hops instead of a search.
```

## Go you'll reach for

- A resolver walking the tree, keeping a stack of scopes.
- A `map[Expr]int` of hop distances, consulted by `GetAt`/`AssignAt`.

## Hints

<details><summary>Nudge</summary>

Globals are not resolved — anything not found in a local scope falls back to
the global environment.
</details>

<details><summary>Approach</summary>

Key the distance map by the expression **node**, not by name: two uses of the
same name in different scopes need different answers.
</details>

<details><summary>The API</summary>

Key the distance map by the expression node itself, not by name: two uses
of the same name in different scopes must resolve to different depths.
</details>
