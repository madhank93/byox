## What this stage teaches

`or` is not a binary operator like `+`, for two reasons. It **short-circuits** —
the right side is not evaluated when the left is truthy — and it returns **one
of its operands**, not a boolean: `nil or "hi"` is `"hi"`, and `1 or 2` is `1`.

That is why it needs its own node type: a `BinaryExpr` case would evaluate both
sides before deciding anything.

## Go you'll reach for

- A `LogicalExpr` node with its own evaluation case.

## Hints

<details><summary>Nudge</summary>

Evaluate the left; if truthy, return it *as is* without touching the right.
</details>

<details><summary>Approach</summary>

Give it its own node type. A binary case would evaluate both sides before
deciding, which is exactly what short-circuiting forbids.
</details>
