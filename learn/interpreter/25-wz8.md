## What this stage teaches

What the parser does when the tokens do not fit the grammar: report the
offending token and exit **65**, the same code as a scan error. Both are
"your source is malformed", detected at different phases, so they share an
exit code — runtime errors get their own later.

## Go you'll reach for

- `[line N] Error at '<lexeme>': Expect expression.` on stderr.
- `Error at end:` when the offending token is EOF.

## Hints

<details><summary>Nudge</summary>

`(72 +)` fails at the `)`, which cannot start an expression.
</details>

<details><summary>Approach</summary>

Reaching `primary()` with a token that begins nothing is the general failure —
one error site covers most malformed input.
</details>
