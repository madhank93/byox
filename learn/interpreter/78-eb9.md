## What this stage teaches

`init` bends two rules. A bare `return;` inside it is allowed and returns
**the instance**, not nil — and `return value;` is a static error, because a
constructor that produced something other than the object it built would break
every caller's assumption.

Calling `init()` directly on an existing instance also returns that instance,
which is why the rule is about the value rather than about construction.

## Go you'll reach for

- An `isInitializer` flag on `LoxFunction`; the resolver's function context
  distinguishing an initializer.

## Hints

<details><summary>Nudge</summary>

`Can't return a value from an initializer.`
</details>

<details><summary>Approach</summary>

Flag the function as an initializer at declaration time; both the bare
return and the value-return rule read that flag.
</details>
