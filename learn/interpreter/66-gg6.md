## What this stage teaches

A function's call environment hangs off the environment where the function was
**defined**, not where it was called. That one choice is the whole of closures:
a returned inner function keeps working because the chain it captured is still
reachable through it, even though the outer call has returned.

Hanging it off the *caller's* environment instead would give you dynamic
scoping — a different language, and one where a function's meaning depends on
who calls it.

## Go you'll reach for

- A `Closure *Environment` field on `LoxFunction`, set at declaration time.

## Hints

<details><summary>Nudge</summary>

`makeCounter()` returning an inner function that increments a captured variable
is the canonical test.
</details>

<details><summary>Approach</summary>

Go's garbage collector keeps the captured environment alive for you — in a
language with manual memory management this is where closures get hard.
</details>
