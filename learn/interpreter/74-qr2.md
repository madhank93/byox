## Core concept

Methods live on the **class**, fields on the **instance**, and a property
access checks fields first, then methods. That order is a real language
decision: a field can shadow a method of the same name, which is how you would
store a function in a field and call it.

## Go APIs

- A `Methods map[string]FunctionStmt` on `LoxClass`.
- Field lookup, then method lookup, in `LoxInstance.Get`.

## Hints

<details><summary>Nudge</summary>

Method declarations inside a class body have no `fun` keyword.
</details>

<details><summary>Approach</summary>

Check the instance's fields before the class's methods. That order is what
lets a field shadow a method of the same name.
</details>
