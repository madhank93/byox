## Core concept

`var a = a;` inside a local scope is an error the **resolver** catches, before
anything runs. The mechanism is a two-step declaration: a name is first marked
"declared but not ready", and only marked ready after its initializer is
resolved — so reading it in its own initializer is detectable.

## Go APIs

- A `map[string]bool` per scope: false while declaring, true once defined.

## Hints

<details><summary>Nudge</summary>

`Can't read local variable in its own initializer.`
</details>

<details><summary>Approach</summary>

At the top level this is allowed — globals are not resolved, so the rule only
applies inside a local scope.
</details>
