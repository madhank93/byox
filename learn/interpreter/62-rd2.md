## What this stage teaches

`return` has to unwind an arbitrary depth of nested statements — out of a loop,
out of an `if`, out of a block — and land at the function call. A tree walker
does that with a **signal that propagates like an error**: a sentinel value the
executor returns upward until `LoxFunction.Call` catches it.

Using the error path for a non-error is a little uncomfortable, and it is what
every tree-walking interpreter does, because the alternative is threading a
"did we return?" flag through every statement type.

```
return has to escape an arbitrary depth:

  fun f() {
    while (true) {          execute(WhileStmt)
      if (x) {                execute(IfStmt)
        return 1;               execute(ReturnStmt) -- raises returnSignal{1}
      }                         |
    }                           | propagates up like an error,
  }                             | past while, past if, past the block
                                v
                        LoxFunction.Call catches it -> value 1

a "did we return?" flag would have to be checked by every statement type.
the signal costs one type and is caught in exactly one place.
```

## Go you'll reach for

- A `returnSignal` type carrying a value; caught in `Call`.

## Hints

<details><summary>Nudge</summary>

`return;` with no value returns `nil`.
</details>

<details><summary>Approach</summary>

Distinguish the signal from a genuine runtime error where you catch it —
letting a real error be swallowed as a return is a nasty bug.
</details>
