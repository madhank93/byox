## What this stage teaches

Two `var a` in the *same local scope* is an error, even though it was fine at
the top level (stage 45). The reasoning: at the REPL redefinition is a
convenience, but inside a function it is almost always a mistake — and the
resolver already tracks exactly what each scope contains, so the check is cheap.

## Go you'll reach for

- An existence check when declaring, skipped for the global scope.

## Hints

<details><summary>Nudge</summary>

`Already a variable with this name in this scope.`
</details>

<details><summary>Approach</summary>

Check the current scope's map before declaring, and skip the check entirely
for globals — the REPL depends on redefinition being allowed there.
</details>
