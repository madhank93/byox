## What this stage teaches

Assignment is an **expression**, not a statement — it produces the assigned
value, which is why `print a = 2;` prints `2` and `a = b = 3` works.

Parsing it needs a trick. The parser reads the left side as an ordinary
expression, then sees `=` and has to reinterpret what it just built as a
**target**. If that expression is not a variable, it is an invalid assignment
target — you cannot assign to `1 + 2`.

## Go you'll reach for

- An `AssignExpr`; `assignment()` sitting at the loosest precedence level.
- `Environment.Assign`, which errors on an undefined name instead of creating it.

## Hints

<details><summary>Nudge</summary>

Assignment is right-associative: `a = b = 3` assigns `3` to both.
</details>

<details><summary>Approach</summary>

Parse the left side, then if `=` follows, check the node type. Backtracking is
not needed — one token of lookahead after the fact is enough.
</details>
