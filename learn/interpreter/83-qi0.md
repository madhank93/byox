## Core concept

`super.method()` means "start the lookup one class **above where this method was
defined**" — and that is not the same as "above the object's class". In a
three-level hierarchy, a method inherited from the middle class must resolve
`super` against the top class, not against its own runtime type; otherwise a
call chain can loop forever.

Lox gets it right by making `super` lexical: the resolver records how far up
the environment chain the superclass sits, and each method's closure is wrapped
in an environment defining `super` at declaration time.

## Go APIs

- A `SuperExpr`; an environment layer holding `super` around each method's closure.
- The resolver's distance map, then rebinding the found method to `this`.

## Hints

<details><summary>Nudge</summary>

`super` resolves the method, then binds it to the current instance — so the
inherited method still sees the right `this`.
</details>

<details><summary>Approach</summary>

Two environments wrap a method: one defining `super`, one defining `this`. The
order matters, and the resolver's hop counts assume it.
</details>
