## What this stage teaches

The first error path, and the convention that holds for the rest of the
course: errors go to **stderr**, tokens still go to stdout, and the process
exits **65**. Scanning does not stop at the first bad character — it reports
and keeps going, so one typo does not hide every other token.

That "report and continue" choice is what lets a compiler show you ten errors
instead of making you fix them one run at a time.

## Go you'll reach for

- `fmt.Fprintf(os.Stderr, "[line %d] Error: Unexpected character: %s\n", ...)`.
- A `hadError` flag consulted at exit.

## Hints

<details><summary>Nudge</summary>

Exit 65 if any lexical error occurred, 0 otherwise — after printing all tokens.
</details>

<details><summary>Approach</summary>

Build the error reporting now rather than retrofitting it. Nearly every later
stage adds a message to it, and the tester compares them exactly.
</details>
