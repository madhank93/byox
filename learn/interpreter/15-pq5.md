## What this stage teaches

Keywords look exactly like identifiers, so the scanner does not try to match
them directly. It scans an identifier, then **looks the text up** in a keyword
table: a hit becomes `AND`, `CLASS`, `IF`…, a miss stays `IDENTIFIER`.

Doing it this way means `orchid` scans as one identifier rather than `or`
followed by `chid` — matching keywords first would produce exactly that bug.

## Go you'll reach for

- `map[string]string` from keyword text to token type.

## Hints

<details><summary>Nudge</summary>

The sixteen: `and class else false for fun if nil or print return super this
true var while`.
</details>

<details><summary>Approach</summary>

Scan the whole identifier first, then classify. This is the last scanning
stage — from here the tokens feed a parser.
</details>
