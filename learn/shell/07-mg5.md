## What this stage teaches

`PATH` is a colon-separated list searched **in order**, and a candidate counts
only if it exists and is executable. Order is what lets a directory earlier in
`PATH` shadow a system binary — the mechanism behind every "why is it running
the wrong version" problem.

## Go you'll reach for

- `strings.Split(os.Getenv("PATH"), string(os.PathListSeparator))`.
- `os.Stat` plus a permission-bit check, or `exec.LookPath` to do both.

## Hints

<details><summary>Nudge</summary>

Return the first match; do not keep looking for a "better" one.
</details>

<details><summary>Approach</summary>

Return the first executable match and stop. A later directory shadowing an
earlier one is the bug this ordering exists to prevent.
</details>
