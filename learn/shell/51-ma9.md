## What this stage teaches

A finished background process stays in the process table as a **zombie** until
its parent collects the exit status. The shell must therefore notice completion
— and notice it *without blocking*, because calling `Wait` directly would hang
the prompt until the job finished.

The Go idiom: a goroutine per job calling `Wait` and closing a channel, which
the shell then polls with a non-blocking `select`.

```
one background job's life:

  cmd &          Start()          exits            reaped
    |               |               |                 |
    v               v               v                 v
  [ table ]---->[ Running ]---->[ zombie ]------>[ removed ]
                    |            (still in         "[1]+ Done"
                    |             the process       printed, number
                    |             table until       freed for reuse
                    |             Wait() is
                    |             called)
                    |
      goroutine: cmd.Wait(); close(done)   <-- collects the status
                                               without blocking the prompt

  the shell polls  select { case <-done: reaped  default: still running }
```

## Go you'll reach for

- `Done chan struct{}` on the job; `go func() { cmd.Wait(); close(done) }()`.
- `select { case <-j.Done: ... default: }`.

## Hints

<details><summary>Nudge</summary>

A finished job prints as `Done` and leaves the table.
</details>

<details><summary>Approach</summary>

`Wait` must be called exactly once per process; letting the goroutine own it
keeps that true.
</details>
