## What this stage teaches

An unset variable expands to the **empty string**, not an error and not the
literal text. That is a deliberate and slightly dangerous choice — it is why
`rm -rf "$PREFIX/"` on an unset `PREFIX` is a famous way to destroy a machine,
and why careful scripts run `set -u`.

The last stage of the course, and a fitting one: the shell's defaults are
convenient first and safe second, which is exactly the trade you have been
implementing all along.

## Go you'll reach for

- A map lookup whose miss yields `""`.

## Hints

<details><summary>Nudge</summary>

`echo "[$UNSET]"` prints `[]`.
</details>

<details><summary>Approach</summary>

Empty is not the same as absent — `declare -p` still reports an unset name as
not found.
</details>
