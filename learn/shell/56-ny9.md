## What this stage teaches

A builtin in a pipeline has no process to attach a pipe to — it runs **inside
the shell**, so its output has to be written into the pipe by hand. That is why
builtins should take a writer rather than printing to stdout directly: the same
`echo` implementation then works standalone, redirected, and piped.

Real bash runs builtins in a subshell for this; here, writing to the pipe and
closing it is enough.

## Go you'll reach for

- A builtin signature taking `out, errOut io.Writer`.

## Hints

<details><summary>Nudge</summary>

Close the pipe's write end after the builtin returns, or the next command waits
forever.
</details>

<details><summary>Approach</summary>

Give every builtin the signature `(args []string, out, errOut io.Writer)`.
The standalone path passes `os.Stdout`; the pipeline path passes the pipe's
write end, and nothing else changes.
</details>
<details><summary>The API</summary>

Close the write end and advance to the next segment after the builtin
returns — it finished synchronously, so there is nothing to wait for.
</details>
