## Core concept

`history -a` appends only what is **new since the last write**, which is how
concurrent shells share one history file without clobbering each other. Doing
that needs a high-water mark: how many entries have already been persisted, so
the next append starts there.

## Go APIs

- A `historyFlushed int` counter, updated after every write or append.
- `os.OpenFile` with `O_APPEND`.

## Hints

<details><summary>Nudge</summary>

`-w` also moves the mark — everything is persisted after it.
</details>

<details><summary>Approach</summary>

Loading with `-r` moves the mark too, or entries just read from the file get
appended straight back into it.
</details>

<details><summary>Implementation</summary>

`history[historyFlushed:]` is exactly the unwritten tail. Set
`historyFlushed = len(history)` after every write, append or load, or the
next append duplicates entries.
</details>
