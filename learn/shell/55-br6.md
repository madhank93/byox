## What this stage teaches

A pipeline connects one process's stdout to the next one's stdin through a
kernel pipe. The rule that matters: **start every process before waiting for
any of them**. Start-and-wait in sequence deadlocks as soon as the first
command's output exceeds the pipe buffer — it blocks writing, and nothing is
reading yet.

The other trap is file descriptors. The parent must close its copy of the write
end, or the reader never sees EOF and the pipeline hangs with both processes
alive.

```
ls | wc -l   -- one pipe, two processes

        +-----------+          +-----------+
        |    ls     |          |   wc -l   |
        | stdout ---+--> pipe -+--> stdin  |
        +-----------+          +-----------+
              ^                      ^
              both are STARTED first, then both waited on

the shell holds both ends until it hands them over:

   parent: [read][write]  -->  after Start, parent MUST close its copies
   child1:        [write]      or the reader never sees EOF and hangs
   child2: [read]
```

## Go you'll reach for

- `os.Pipe()`; `cmd.Stdout = writer`, next `cmd.Stdin = reader`.
- `Start` both, close the parent's ends, then `Wait` on both.
