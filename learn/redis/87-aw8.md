## Core concept

A subscribed connection enters a **restricted mode**: only a handful of commands
remain legal (`SUBSCRIBE`, `UNSUBSCRIBE`, `PSUBSCRIBE`, `PUNSUBSCRIBE`, `PING`,
`QUIT`), and everything else is an error. The reason is protocol integrity —
messages arrive on this connection unprompted, so a client cannot reliably match
replies to requests any more.

## Go APIs

- A `subscribed` flag (or `len(channels) > 0`) checked before dispatch.
- `-ERR Can't execute '<cmd>': only (P|S)SUBSCRIBE / (P|S)UNSUBSCRIBE / PING / QUIT / RESET are allowed in this context`

## Hints

<details><summary>Nudge</summary>

`GET` on a subscribed connection is an error, not a value.
</details>

<details><summary>Approach</summary>

Check the mode before the normal command switch, so allowed commands run
unchanged and the restriction lives in one place.
</details>
