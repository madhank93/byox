## What this stage teaches

`AUTH <password>` (or `AUTH <user> <password>`) checks the credential and marks
the connection authenticated. Hash the supplied password and compare against the
stored hash — the plaintext is never stored, so it is never compared.

A wrong password is `-WRONGPASS invalid username-password pair or user is
disabled.`, and note the error *code*: RESP errors lead with a machine-readable
word, and clients branch on it rather than on the message text.

## Go you'll reach for

- `sha256.Sum256` on the supplied password, compared to the stored hash.
- An `authenticated bool` on the connection.

## Hints

<details><summary>Nudge</summary>

Success is `+OK`. With `nopass` set, any password succeeds.
</details>

<details><summary>Approach</summary>

`crypto/subtle.ConstantTimeCompare` is the habit worth forming for secret
comparison, even though these are hashes and the tester won't check.
</details>
