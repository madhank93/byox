## Core concept

`XREAD streams k1 k2 id1 id2` puts **all the keys first, then all the ids**.
It is an unusual layout — most commands interleave — and it exists so the parser
can find the split without knowing how many streams there are: everything after
`streams` divides in half.

## Go APIs

- `n := len(rest) / 2`, then `keys := rest[:n]`, `ids := rest[n:]`.

## Hints

<details><summary>Nudge</summary>

The reply keeps the streams in the order they were requested.
</details>

<details><summary>Approach</summary>

A stream with no new entries is omitted from the reply entirely, not included as
an empty array.
</details>
