## What this stage teaches

`ACL GETUSER <username>` describes a user as a flat array of alternating
property names and values — `flags`, `passwords`, and so on — the same
no-map-type-in-RESP2 workaround `CONFIG GET` uses. A user that doesn't exist
gets a null array.

## Go you'll reach for

- The nested-array encoder: property names as bulk strings, values as nested
  arrays.

## Hints

<details><summary>Nudge</summary>

Only `default` needs to exist at this stage.
</details>

<details><summary>Approach</summary>

The tester checks the properties it cares about rather than the exact shape of
the whole reply, so extra fields are tolerated — but the ones it names must be
present and correctly typed.
</details>
