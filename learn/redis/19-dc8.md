## Core concept

Here is the neat part of AOF: the log format is RESP — the same array-of-bulk-
strings the client sent. So "write to the AOF" means re-encoding the parsed
command, and "replay the AOF" means feeding those bytes back through the parser
you already have. One format, one parser, both directions.

## Go APIs

- An encoder that turns `[]string` back into `*N\r\n$len\r\narg\r\n…`.
- `file.Write(encoded)` after the command has been applied.

## Hints

<details><summary>Nudge</summary>

Log the command as received — same arguments, same order.
</details>

<details><summary>Approach</summary>

Write the encoder as the inverse of your parser and test them against each
other. It is also exactly what replication propagation needs at stage 34.
</details>

<details><summary>Implementation</summary>

Append after applying, not before: a command that fails validation should not be
in the log.
</details>
