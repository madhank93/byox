## What this stage teaches

The keyspace arrives, and with it the first genuinely shared mutable state in
the program. Every connection goroutine reads and writes one map, so it needs a
`sync.Mutex` — and it needs one now, while the map is simple, rather than after
five more data types are layered on it.

The other lesson is the **null bulk string**, `$-1\r\n`: Redis distinguishes
"the key holds an empty string" from "the key does not exist", and the wire
format has a distinct encoding for the second.

## Go you'll reach for

- `map[string]string` plus `sync.Mutex` (or `sync.RWMutex`).
- `mu.Lock()` / `defer mu.Unlock()` around every access.
- `+OK\r\n` for `SET`, `$-1\r\n` for a missing `GET`.

## Hints

<details><summary>Nudge</summary>

`GET` on a key that was never set is not an error — it is a null bulk string.
</details>

<details><summary>Approach</summary>

Put the map and its mutex behind two small functions (`get`, `set`) rather than
locking inline in the command switch. The stages that add expiry, transactions
and replication all extend those two functions.
</details>

<details><summary>The API</summary>

Run the tests with `-race` in the back of your mind: an unguarded map that works
under a single-client test panics under a concurrent one with
"concurrent map writes".
</details>
