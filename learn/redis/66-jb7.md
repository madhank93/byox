## What this stage teaches

`WATCH key` marks a key: if anyone modifies it before this connection's `EXEC`,
the transaction is abandoned. That is **optimistic concurrency control** — no
lock is taken, work proceeds assuming no conflict, and the conflict is detected
at commit time. It is check-and-set built out of two commands.

## Go you'll reach for

- A per-connection `watched map[string]uint64` — key to the version seen.
- `+OK\r\n`.

## Hints

<details><summary>Nudge</summary>

At this stage `WATCH` only has to record the key and reply `+OK`.
</details>

<details><summary>Approach</summary>

Decide now how "modified" will be detected — a per-key version counter is the
simplest thing that works, and stage 68 needs it.
</details>
