## What this stage teaches

`EXEC` clears the watch set whether it committed or aborted. The watches existed
to protect *this* transaction; carrying them forward would abandon a later,
unrelated transaction for a change that has already been accounted for.

## Go you'll reach for

- The `resetTransaction()` from stage 63, extended to clear watches.

## Hints

<details><summary>Nudge</summary>

Both paths — committed and abandoned — clear the watches.
</details>

<details><summary>Approach</summary>

If reset lives in one function called from every exit path, this stage is one
line. If it doesn't, this is the moment to make it so.
</details>
