## What this stage teaches

`INCR` on an existing integer key. It looks like a trivial command and is the
canonical example of a **read-modify-write**: read, add one, store, reply with
the new value — all of which must happen without another goroutine interleaving,
or two concurrent `INCR`s produce one increment.

## Go you'll reach for

- `strconv.Atoi` / `strconv.Itoa` — the value is stored as a string.
- One lock held across the whole read-modify-write.

## Hints

<details><summary>Nudge</summary>

The reply is an integer (`:6\r\n`), even though the stored value is a string.
</details>

<details><summary>Approach</summary>

Do not lock, read, unlock, then lock again to write. That gap is the bug this
command exists to teach.
</details>
