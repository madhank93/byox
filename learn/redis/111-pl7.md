## Core concept

The `passwords` property lists a user's credentials — and lists them as
**SHA-256 hashes**, never as the passwords themselves. Redis stores only the
hash, compares hashes at login, and exposes hashes to introspection, so reading
the ACL config never reveals a usable secret.

(Redis uses a plain SHA-256 here, not a slow password KDF like bcrypt or argon2.
That is a deliberate trade for a credential checked on every connection, and it
is why Redis passwords are meant to be long random strings rather than
memorable ones.)

## Go APIs

- `crypto/sha256`, `sha256.Sum256([]byte(password))`.
- `encoding/hex` — the hash is reported as lowercase hex.

## Hints

<details><summary>Nudge</summary>

With `nopass` set, the `passwords` array is empty.
</details>

<details><summary>Approach</summary>

Store hashes on the user struct from the start. A field holding plaintext "for
now" is how plaintext ends up shipped.
</details>
