## What this stage teaches

Several `SUBSCRIBE` calls accumulate, and the reply's count grows with each.
Subscribing twice to the same channel must not count twice — which is why the
per-connection collection wants to be a set rather than a slice.

## Go you'll reach for

- `map[string]bool` per connection; `len()` for the count.

## Hints

<details><summary>Nudge</summary>

One `SUBSCRIBE` naming several channels sends one reply per channel, each with
the running count.
</details>

<details><summary>Approach</summary>

Keep the per-connection set and the server-wide channel map updated together, or
`UNSUBSCRIBE` at stage 91 will leave one of them stale.
</details>
