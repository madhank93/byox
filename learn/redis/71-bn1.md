## What this stage teaches

`UNWATCH` forgets every watched key on this connection. A client that decides not
to proceed should release its watches rather than carry stale versions into an
unrelated transaction later — the watch set is per-connection and outlives any
single `MULTI` unless cleared.

## Go you'll reach for

- Clear the connection's `watched` map, reply `+OK\r\n`.

## Hints

<details><summary>Nudge</summary>

`UNWATCH` with no watches is still `+OK`, not an error.
</details>

<details><summary>Approach</summary>

Clear the map rather than reallocating, or reallocate consistently — just don't
leave a nil map that later `WATCH` calls write into.
</details>
