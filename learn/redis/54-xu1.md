## Core concept

`$` means "entries added after this call started". Resolving it is a race in
miniature: you must capture the stream's current last id **at the moment the
command is received**, not when the wait loop first checks. Anything added in
between belongs to the client, and re-resolving `$` inside the loop silently
drops it.

## Go APIs

- Resolve `$` to the current last id under the lock, before entering the wait.

## Hints

<details><summary>Nudge</summary>

`$` on an empty stream resolves to `0-0`.
</details>

<details><summary>Approach</summary>

Resolve every id argument to a concrete id up front, then the wait loop is the
same code for `$` and for an explicit id.
</details>
