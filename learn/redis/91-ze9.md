## What this stage teaches

`UNSUBSCRIBE channel` removes the subscription from both registries — the
connection's set and the server's channel map — and replies with the remaining
count. When that count reaches 0 the connection leaves subscribed mode and normal
commands work again.

Leaving both registries consistent is the point: a stale entry in the server map
means writing to a connection that no longer expects messages.

## Go you'll reach for

- Deletion from both structures, under their locks.
- The three-element reply: `unsubscribe`, channel, remaining count.

## Hints

<details><summary>Nudge</summary>

Unsubscribing from a channel you never joined still replies with the current
count.
</details>

<details><summary>Approach</summary>

Do the same cleanup when a connection closes — a disconnect is an implicit
unsubscribe from everything, and forgetting it leaks entries for the life of the
process.
</details>
