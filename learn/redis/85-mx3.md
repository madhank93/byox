## Core concept

Pub/sub is a different shape from everything so far: messages are not stored,
and a subscriber that isn't connected when a message is published simply misses
it. Fire-and-forget, no persistence, no acknowledgement.

`SUBSCRIBE channel` replies with a three-element array — `subscribe`, the
channel name, and the count of channels this connection now holds.

## Go APIs

- A per-connection set of channels, plus a server-side
  `map[string][]*connection`.
- Both guarded — subscribers are read from other connections' goroutines.

## Hints

<details><summary>Nudge</summary>

The count is per connection, not the number of subscribers on the channel.
</details>

<details><summary>Approach</summary>

Register the connection in the server's channel map now. Stage 90 delivers
through it, from a *different* goroutine — so it needs a lock from the start.
</details>
