## What this stage teaches

One connection carries many commands, so handling a request is a loop, not a
single exchange. This is also where framing starts to matter: the client may
send several commands in one TCP segment, or one command split across two, so
"one read equals one command" is not true and never was.

## Go you'll reach for

- `bufio.NewReader(conn)` created **once**, outside the loop.
- `reader.ReadString('\n')` to consume whole protocol lines.
- `io.EOF` as the signal to stop.

## Hints

<details><summary>Nudge</summary>

Loop until the read errors. Reply once per command received, not once per read.
</details>

<details><summary>Approach</summary>

Let the reader own the buffering. If you allocate a fresh `[]byte` per iteration
and call `conn.Read` directly, you will eventually split a command down the
middle and spend an hour on it.
</details>

<details><summary>The API</summary>

`bufio.Reader` keeps unconsumed bytes between calls, which is exactly the
property that makes it safe here. Wrapping the connection a second time
elsewhere throws those bytes away.
</details>
