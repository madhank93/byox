## What this stage teaches

`EXEC` runs the queue in order and returns an array of every command's reply.
Redis's atomicity guarantee comes from its single thread: nothing interleaves
because nothing else runs. In a goroutine-per-connection server you have to
supply that guarantee yourself — hold the keyspace lock across the whole batch.

## Go you'll reach for

- A loop over `queued`, collecting replies into a buffer.
- One `mu.Lock()` around the entire loop.

## Hints

<details><summary>Nudge</summary>

The outer array's length is the number of queued commands; each element is that
command's normal reply.
</details>

<details><summary>Approach</summary>

Have your command handlers write into an `io.Writer` rather than the connection
directly. Then `EXEC` collects into a `bytes.Buffer` and emits one array — no
special-case reply plumbing.
</details>

<details><summary>The API</summary>

Clear `inMulti` before running, not after: a queued command must not re-queue
itself.
</details>
