## Core concept

Two clients each in their own `MULTI`. This is the stage that proves the
transaction state really is per-connection — if any of it leaked into a
package-level variable back at stage 58, one client's queue now executes on the
other's `EXEC`.

## Go APIs

- Nothing new, if the state was scoped correctly.

## Hints

<details><summary>Nudge</summary>

Each connection's queue is independent; only the keyspace is shared.
</details>

<details><summary>Approach</summary>

If this fails, grep for package-level `var`s holding transaction state. That is
almost always the entire bug.
</details>
