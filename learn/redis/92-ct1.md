## What this stage teaches

A sorted set is a set of unique members, each with a floating-point score,
kept ordered by score. Two properties do all the work: **members are unique**, so
adding an existing member updates its score rather than duplicating it, and
**ties break lexicographically by member name**, so the ordering is total and
deterministic.

`ZADD` returns the number of members *added*, not updated — 0 when the member
already existed.

## Go you'll reach for

- `map[string]float64` per key, plus sorting at read time.
- `strconv.ParseFloat` for the score.

## Hints

<details><summary>Nudge</summary>

`ZADD key 3.7 member` on a new key returns `:1\r\n`.
</details>

<details><summary>Approach</summary>

A map plus sort-on-read is fine at this scale. Real Redis uses a skip list
because it needs ordered access at every operation; you don't.
</details>
