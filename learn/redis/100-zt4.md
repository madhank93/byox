## Core concept

Here is the trick that makes Redis's geo commands work: **there is no geo type.**
`GEOADD` is a sorted set whose score encodes a latitude/longitude pair as a
single 52-bit number, so every sorted-set command already works on geo data, and
proximity search becomes a score range query.

This stage only asks for the argument shape — `GEOADD key lon lat member`, note
longitude before latitude — and the reply is `ZADD`'s added-count.

## Go APIs

- The `ZADD` path, with the score computed rather than parsed.

## Hints

<details><summary>Nudge</summary>

Longitude first. Half the bugs in these eight stages are that ordering.
</details>

<details><summary>Approach</summary>

Store into the same structure your sorted sets use, so `ZSCORE` and `ZRANGE`
keep working on a geo key.
</details>
