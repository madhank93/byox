## Core concept

After `+FULLRESYNC` the master sends its RDB snapshot, and this is **the one
place RESP breaks its own rule**. The payload is framed like a bulk string —
`$<length>\r\n` then the bytes — but there is **no trailing CRLF**. A reader that
assumes every bulk string ends in CRLF eats the first two bytes of the command
stream that follows, and the failure shows up several stages later as a corrupt
propagated command.

```
the one place RESP breaks its own rule:

   a normal bulk string          the RDB transfer
 +------+---------+------+     +------+---------------+
 | $5   | hello   | \r\n  |     | $88  | <88 raw bytes>|
 +------+---------+------+     +------+---------------+
                     ^                                 ^
                     CRLF                              NO trailing CRLF

read exactly the declared length and stop. a reader that also consumes
\r\n here eats the first two bytes of the command stream that follows.
```

## Go APIs

- `encoding/base64` to decode a hardcoded empty-RDB payload.
- `io.ReadFull` on the replica side, reading exactly the declared length.

## Hints

<details><summary>Nudge</summary>

An empty RDB file is a fixed, well-known byte sequence — you do not have to
generate one.
</details>

<details><summary>Approach</summary>

Send the length header and the raw bytes, and stop. On the replica, read exactly
`length` bytes and do not look for CRLF.
</details>

<details><summary>Implementation</summary>

Send it on the same connection, immediately after the `+FULLRESYNC` line, with
nothing between them.
</details>
