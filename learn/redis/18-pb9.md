## Core concept

The manifest (`<basename>.manifest`) lists which files make up the AOF and what
each one is:

```
file appendonly.aof.1.incr.aof seq 1 type i
```

It exists because modern AOF is multi-part: a base file plus incrementals, with
rewrites producing new generations. A reader consults the manifest rather than
globbing the directory, so recovery is deterministic even mid-rewrite.

## Go APIs

- `os.WriteFile` for the manifest line.
- Line-oriented text, not RESP — the manifest is the one plain-text piece here.

## Hints

<details><summary>Nudge</summary>

One line, terminated with a newline. `type i` means incremental; a base file
would be `type b`.
</details>

<details><summary>Approach</summary>

Write the manifest whenever you create the incremental file, so the two never
disagree — a manifest naming a file that doesn't exist is worse than no manifest.
</details>
