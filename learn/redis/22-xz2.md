## What this stage teaches

Startup recovery. The log is RESP, so replay is: open the file, parse commands
out of it, and run them — ideally through the **same dispatcher** the network
path uses. A second, replay-only code path is where state divergence bugs breed:
it drifts from the real one the moment a command gains a behaviour.

## Go you'll reach for

- `bufio.NewReader(file)` — the same parser, over a file instead of a socket.
- The existing command dispatch, with replies discarded.

## Hints

<details><summary>Nudge</summary>

Replay before accepting connections, so the first client sees a fully restored
keyspace.
</details>

<details><summary>Approach</summary>

Give the dispatcher a way to write replies nowhere (`io.Discard`) instead of a
separate apply function. That is what keeps replay and live traffic in sync.
</details>

<details><summary>The API</summary>

Commands replayed from the log must not be appended to the log again. Guard the
append while replaying.
</details>
