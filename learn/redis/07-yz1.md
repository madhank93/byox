## What this stage teaches

`SET key value PX 100` attaches a deadline. The design question is *when* the
key disappears, and Redis's answer is **lazily**: nothing sweeps the keyspace on
a timer for correctness — a read checks the deadline and treats an expired key as
missing. That makes expiry a property of the read path, not a background job.

It is also your first command with optional arguments, so the parser stops being
a fixed-arity `switch` and starts scanning the tail.

## Go you'll reach for

- A struct value: `struct { value string; expireAt time.Time }`.
- `time.Now().Add(time.Duration(ms) * time.Millisecond)`.
- `expireAt.IsZero()` to mean "no expiry", so the zero value is correct by default.

## Hints

<details><summary>Nudge</summary>

`GET` on an expired key returns the same `$-1\r\n` as a key that never existed.
</details>

<details><summary>Approach</summary>

Scan the arguments after the value for a `PX` (case-insensitively) followed by a
number. Ignoring options you don't recognise is the right behaviour for these
stages.
</details>

<details><summary>The API</summary>

A `time.Time` zero value comparing false for "has expiry" saves a second bool
field. `time.Now().After(expireAt)` is the check.
</details>
