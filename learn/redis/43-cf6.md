## What this stage teaches

A stream is an append-only log of entries, each with an id and a set of
field/value pairs. The id has the shape `<millisecondsTime>-<sequenceNumber>`,
and it is the whole design: ids are ordered, so a stream is sorted by
construction and a reader can resume from "everything after id X" without any
extra bookkeeping.

## Go you'll reach for

- `type entry struct { ms, seq uint64; fields []string }`.
- A `[]entry` per stream key, appended to.

## Hints

<details><summary>Nudge</summary>

`XADD key id field value` — reply with the id as a bulk string.
</details>

<details><summary>Approach</summary>

Store the id as two integers, not a string. Every later stage compares ids, and
string comparison gets `10-1` versus `9-1` wrong.
</details>
