## What this stage teaches

Delivery: the publishing client's goroutine writes into every subscriber's
connection. This is the same cross-connection hazard as replica propagation at
stage 34, and it needs the same answer — a **per-connection write mutex**, so
two publishers can't interleave halves of two messages into one subscriber's
stream.

The message is a three-element array: `message`, the channel, the payload.

## Go you'll reach for

- A `sync.Mutex` per connection, held around every write to it.
- The subscriber list copied under the map lock, then written outside it.

## Hints

<details><summary>Nudge</summary>

The publisher gets its integer count; each subscriber gets the three-element
array.
</details>

<details><summary>Approach</summary>

If the same connection is both publisher and subscriber, a non-reentrant mutex
deadlocks. Copy first, then write.
</details>

<details><summary>The API</summary>

A subscriber whose write fails has gone away — drop it rather than failing the
publish.
</details>
