## What this stage teaches

A command that fails inside `EXEC` does not abort the transaction — its error
becomes one **element** of the reply array, and the rest still run. Redis
transactions are not rollbacks: they guarantee isolation and ordering, not
all-or-nothing.

This surprises people, and it is a deliberate design choice. Redis's position is
that command errors are programming bugs, and rollback machinery would cost
every transaction to paper over them.

## Go you'll reach for

- Error replies written into the collected array like any other reply.

## Hints

<details><summary>Nudge</summary>

`SET foo bar`, `INCR foo`, `SET bar 5` inside a transaction returns three
elements — the middle one an error.
</details>

<details><summary>Approach</summary>

If your handlers already write to a writer, this needs no new code: an error is
just bytes written like anything else.
</details>
