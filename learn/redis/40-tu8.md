## Core concept

Replicas are attached but no writes have happened, so every replica is trivially
up to date and `WAIT` returns the replica count at once. The rule underneath:
`WAIT` compares each replica's acknowledged offset against the master's current
offset. When the master's offset hasn't moved, everyone already matches.

## Go APIs

- The replica list, and the master's own offset counter.

## Hints

<details><summary>Nudge</summary>

Don't send `GETACK` when there is nothing to acknowledge — return the count
immediately.
</details>

<details><summary>Approach</summary>

Track whether any write has been propagated since the last synchronisation. That
flag is what separates this stage's fast path from the next stage's slow one.
</details>
