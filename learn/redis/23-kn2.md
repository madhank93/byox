title: Replay multiple commands
concepts: [networking]

## Core concept

Replay until the file is exhausted, which makes `io.EOF` a normal ending rather
than an error. A truncated final command — the process died mid-write — is the
case worth thinking about: real Redis tolerates it by stopping at the last
complete command, and treating any parse failure as fatal would make a crash
unrecoverable.

## Go APIs

- A `for` loop that breaks on `io.EOF`.
- `errors.Is(err, io.EOF)` rather than `err == io.EOF`.

## Hints

<details><summary>Nudge</summary>

Same loop as the connection handler, different reader. If they look different,
they probably shouldn't be.
</details>

<details><summary>Approach</summary>

Stop cleanly at EOF, including a partial trailing command, and let everything
already parsed stand.
</details>
