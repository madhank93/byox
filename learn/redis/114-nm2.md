## What this stage teaches

Authentication is worth nothing until it is enforced. When a password is
configured, every command except `AUTH` on an unauthenticated connection must
fail with `-NOAUTH Authentication required.` — and the gate belongs in **one
place**, before dispatch, so a command added later is protected by default
rather than by remembering.

That is fail-closed design: the safe behaviour is what happens when you forget.

## Go you'll reach for

- A check at the top of the dispatcher, before the command switch.

## Hints

<details><summary>Nudge</summary>

`AUTH` itself must remain reachable, or nobody can ever authenticate.
</details>

<details><summary>Approach</summary>

Gate on "a password is configured AND this connection has not authenticated".
With `nopass`, no gate applies.
</details>

<details><summary>The API</summary>

A per-command allowlist scattered through the switch is the anti-pattern here —
one command added without its check is a silent hole.
</details>
