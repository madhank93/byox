## What this stage teaches

AOF is the other persistence strategy: instead of snapshotting the keyspace, log
every write command and replay the log at startup. This stage only asks for the
configuration surface — `appendonly`, `appenddirname` — but it is worth
understanding the trade the config describes. RDB is compact and loses the
writes since the last snapshot; AOF is durable to the last command and grows
without bound.

## Go you'll reach for

- The `CONFIG GET` handler from stage 8, extended with two more parameters.

## Hints

<details><summary>Nudge</summary>

Defaults are `appendonly` = `no` and `appenddirname` = `appendonlydir`.
</details>

<details><summary>Approach</summary>

Hold config in one map rather than a growing list of fields. `CONFIG GET`
becomes a lookup, and the next stage's flags become writes into the same map.
</details>
