## What this stage teaches

The log file itself. Redis names its incremental AOF `<basename>.1.incr.aof`,
and the naming is not cosmetic: the manifest in the next stage refers to files by
these names, and a rewrite produces a new generation with a higher sequence
number.

Open it in append mode. Truncating on open destroys exactly the data AOF exists
to protect.

## Go you'll reach for

- `os.OpenFile(path, os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0o644)`.
- Keep the handle open for the process's life rather than reopening per write.

## Hints

<details><summary>Nudge</summary>

Default basename is `appendonly.aof`, so the incremental file is
`appendonly.aof.1.incr.aof` inside the append directory.
</details>

<details><summary>Approach</summary>

`O_APPEND` makes every write land at the end regardless of file position, which
is what keeps concurrent writers from overwriting each other.
</details>
